# Облачный архиватор vvot27

Клиент отправляет имя файла и публичный HTTP(S)-адрес на служебный домен API Gateway. Шлюз проверяет JSON и ставит задание в Message Queue. Триггер передаёт одно сообщение функции. Функция сохраняет ZIP в закрытый бакет и записывает поля `name`, `url` и `key` в документную таблицу YDB `archives`.

| Запрос | Результат |
| --- | --- |
| `POST /tasks` | `202` при приёме задания, `400` для некорректного тела |
| `GET /archives` | Массив записей из операции YDB Scan |
| `GET /archives/{key}` | Запись об архиве или `404` |
| `GET /download/{key}` | ZIP-файл или `404` |

## Файлы проекта

- `openapi.yaml` задаёт маршруты, проверку тела и прямые интеграции с YMQ, YDB и Object Storage. Terraform подставляет адреса и идентификаторы при создании шлюза.
- `function/main.py` обрабатывает сообщение триггера. Время отправки и уникальный ID сообщения формируют ключ UUIDv7. При повторной доставке функция использует тот же ключ и может завершить запись в YDB после успешной загрузки ZIP.
- `function/source.py` загружает исходный файл по частям. Каждый переход по HTTP-редиректу проходит проверку адреса. Архив временно занимает место в файловой системе функции.
- `versions.tf` и `variables.tf` определяют провайдеры и три входных параметра. `iam.tf`, `queues.tf`, `storage.tf`, `function.tf` и `gateway.tf` составляют одну корневую конфигурацию.

## Запуск из Ubuntu

Понадобятся Terraform версии от 1.5 до 2.0 (исключая 2.0), доступ к реестру провайдеров или его зеркалу и Python 3.9+ для проверок. Облачная функция использует Python 3.12 и стандартную библиотеку. Команды выполняются из корня репозитория.

1. Выбери учебный каталог Yandex Cloud. Учётной записи нужны права создавать ресурсы и сервисные аккаунты, выпускать статический ключ и назначать роли в каталоге. Получи IAM-токен. Если в контейнере настроен `yc`, используй следующий пример, подставив ID и глобально уникальное имя бакета.

   ```bash
   export YC_TOKEN="$(yc iam create-token)"
   export TF_VAR_cloud_id='ID_ОБЛАКА'
   export TF_VAR_folder_id='ID_КАТАЛОГА'
   export TF_VAR_bucket_name='vvot27-your-unique-suffix'
   ```

   Суффикс имени бакета замени строчными латинскими буквами, цифрами или дефисами. Если токен выпущен вне контейнера, передай его через окружение. Статический ключ для управления совместимыми API создаёт Terraform. State содержит этот ключ и должен оставаться в защищённом месте до удаления ресурсов.

2. Проверь функцию и конфигурацию, затем посмотри план и разверни систему.

   ```bash
   python3 -B -m unittest discover -s tests -v
   terraform init
   terraform fmt -check
   terraform validate
   terraform plan -out=deploy.tfplan
   terraform apply deploy.tfplan
   API="$(terraform output -raw api_url)"
   ```

3. Запусти проверку всех четырёх маршрутов на развёрнутой системе. Скрипт отправляет задание с уникальным именем, ждёт появления записи, проверяет UUIDv7, метаданные и содержимое скачанного ZIP. Также проверяются некорректное задание и оба ответа `404`. Для сравнения содержимого используется текст RFC 9562 с сайта RFC Editor.

   ```bash
   python3 tests/smoke.py "$API"
   ```

   Для показа запросов вручную можно использовать `curl`.

   ```bash
   curl -i -H 'Content-Type: application/json' \
     -d '{"name":"example.txt","url":"https://www.rfc-editor.org/rfc/rfc9562.txt"}' \
     "$API/tasks"
   curl -sS "$API/archives"
   # Когда появится запись example.txt, подставь её ключ.
   KEY='UUID_ИЗ_ОТВЕТА.zip'
   curl -sS "$API/archives/$KEY"
   curl -fS "$API/download/$KEY" -o /tmp/vvot27-demo.zip
   unzip -l /tmp/vvot27-demo.zip
   ```

4. Для проверки очереди необработанных заданий отправь синтаксически корректное задание с недоступным источником. Шлюз ответит `202`, а функция завершится ошибкой. Проверь очередь `vvot27-failed` в консоли Message Queue после истечения таймаута видимости 900 секунд. Для записи скринкаста это задание можно отправить заранее.

   ```bash
   curl -i -H 'Content-Type: application/json' \
     -d '{"name":"missing.txt","url":"https://unreachable.invalid/file"}' "$API/tasks"
   ```

5. Закончив проверку, удали ресурсы из той же рабочей директории. `force_destroy` у бакета позволяет Terraform удалить и созданные архивы.

   ```bash
   terraform destroy
   terraform state list
   ```

После успешного удаления список ресурсов в state будет пустым. В публичный Git-репозиторий включи исходники и созданный командой `terraform init` файл `.terraform.lock.hcl`. State, сохранённые планы, локальные значения переменных и собранный ZIP перечислены в `.gitignore`.
